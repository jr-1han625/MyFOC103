# 底层驱动拆分

OLED、LED、Key、Delay 已完成拆分；当前新增 MotorIo 软件驱动与 motor_board 硬件实现，电机启动及接线详见《首次试转与接线》。FOC 基本公式保持原样。

| 层 | 文件 | 职责 |
| --- | --- | --- |
| L0 | `Hardware/*.c`、`board.h` | STM32 时钟、引脚、寄存器、OLED 总线事务、屏器件配置与上电等待、微秒硬件等待 |
| L1 | `L1_Drivers/*.c/.h` | 显示排版/字模/数字格式化、按键消抖与释放等待、LED 翻转、毫秒/秒延时分段 |
| L4 | `User/driver_assembly.c`、`main.c` | 静态 A 表、绑定顺序、哪些器件初始化及何时调用软件能力 |

每个 L1 模块保留 A/B 两个结构体：`*_Hardware` 是硬件能力契约，`*_Software` 是软件能力，唯一只读 B 表为 `OLED_B`、`LED_B`、`Key_B`、`Delay_B`、`MotorIo_B`。L4 的 A 表具有整个程序生命周期，L1 只保存表引用，没有硬件状态镜像、运行时 ID 查找或业务依赖。

启动先 `Drivers_Bind()`，再按实际需求初始化。当前初始化 MotorIo 与 OLED；LED/Key 引脚仍未初始化。OLED 初始化顺序仍是原上电等待、GPIO 配置、器件命令、清屏。老显示 API 名称保留为 L1 实际实现，主入口通过 B 使用。

迁移 MCU 时重写 L0 并更新 L4 的 A 表，L1 不引用 STM32 头文件、GPIO 类型或寄存器。硬件层不只保留初始化：实际读写、总线事务和硬件等待也必须在 L0，不能把它们搬进可移植的软件能力中。

原行为保留：LED 低电平点亮且翻转读取真实锁存器；按键每次按下/释放各等 20 ms，按住时阻塞，按键 2 后处理并覆盖返回键码；延时仍按每 1000 us 累加毫秒。原 OLED 事务不读取 ACK，保持该限制。屏字模文件按原字节移动，显示格式化不新增参数裁剪。

Delay 的原实现按 72 MHz 使用 SysTick，单次硬件微秒等待范围仍为 0~233015 us，且会改写 SysTick 配置；本次没有把它变成周期中断调度器。按键与显示的阻塞调用只用于前台，不可放进 FOC 电流环中断。没有进行实机时序测试，因此不承诺接口间接调用后 GPIO 总线边沿间隔逐周期不变。

`test_drivers.c` 用模拟 A 表检验软件调用流，不依赖 STM32；`driver_test_results.txt` 保存主机结果，`keil_build.log` 保存目标构建结果。`before_driver_split.zip` 保留修改前源文件，供恢复使用，不参与编译。

主机驱动测试仅关闭原字模数组扁平初始化产生的 `missing-braces` 风格告警，其余使用 `-Wall -Wextra -Werror -pedantic`。不为消除该告警改写字模，确保字模原始字节不变。

电机端口的硬件 A 表返回 PWM 满计数、ADC 满码及有效采样窗口允许的占空比上下限。L1 依据该能力校验/量化占空比并完成零点平均，不持有 STM32 外设类型或固定的物理引脚；L0 拥有双 ADC、TIM1、TIM2 及 DRV8323 校准时序。
